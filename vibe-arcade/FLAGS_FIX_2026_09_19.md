# Image flags, 2026-09-19

## Report
The user's screenshots show regional-indicator text `KR` rather than a visible South Korean flag. The old `C.flag()` helper returned an emoji string; previous tests checked that string, not a decoded image. This is a rendering/QA gap, not a country-account data problem.

## Change
- Render actual SVG `<img>` flags alongside names on game-specific and overall player/country boards, the profile title and selected-country previews.
- Existing Orbit/Arcade 3 header labels are upgraded by a narrowly scoped observer attached only to `#playerLink` and `#identity`. Gameplay/controller logic and score versions are unchanged.
- Keep native select options as accessible country-name/code text; display the selected flag as a separate SVG preview rather than relying on unsupported images in native `<option>` elements.
- No country choice => neutral placeholder; asset failure => the correct ISO code, not another country's flag. All label values are inserted as text, never innerHTML.

## Assets and costs
Use MIT-licensed lipis/flag-icons v7.5.0. Pinned npm lockfile includes the tarball integrity hash. Build copies the 249 allowlisted SVG images and LICENSE.txt into `/assets/flags/7.5.0/`, served and cached by the existing Vercel site. No third-party image requests are made by visitors, no new DB/paid service/generation job, and no score/account writes in this change.

Sources: https://github.com/lipis/flag-icons and its LICENSE.
Build locally: `cd vibe-arcade && npm ci --ignore-scripts && npm run build`.
