## 4-1: 지금 만들어진 측정 범위

`page_view → game_open → game_start → game_finish / replay → ranked_entry / ranked start → client score-save report`의 사이트 내부 관측을 한 계약으로 정리했다. SNS 노출·시청 시간·프로필 클릭의 플랫폼 수치를 새 DB에 자동 수집하는 기능은 아직 아니다. 모든 퍼널 단계를 개인 단위로 연결했다고 주장하지 않는다.

`ig/instagram`, `yt/youtube`, `tt/tiktok`, `th/threads`를 정규화하되 원래 유입 태그는 보존한다. 기존 `flag_challenge_pilot_20260920` 캠페인이나 게시된 URL을 `flag_challenge`로 덮어쓰지 않았다. 공통 프로필 링크는 채널 수준으로만 집계하며 특정 영상의 전환으로 만들어 넣지 않는다. `content_tagged`도 전달된 링크의 관측 분류이지 인과관계나 실제 시청 인증은 아니다.

매 시작마다 시도 ID를 부여하고 중복 종료·재플레이 이벤트를 제거한다. 이전 간단 게임 6종은 재시작 시 `game_start` 대신 `replay`만 보내는 구조여서, 이 호환 경로를 별도로 수정했다. 첫 판 이후의 플레이와 종료 기록이 사라지는 문제를 회귀 시험으로 차단했다.

세션은 임의의 탭 ID, 30분 비활동/새 유입 시 재설정, 서버의 UTC 일자별 키 해시로 처리한다. 따라서 고유 사람 수나 다음 날 재방문율이 아니다. 브라우저의 score_verified 메시지도 공식 국가 점수의 대체물이 아니다.

## 비공개 저장소·제외·보관

Supabase에 기존 서비스와 분리한 `loopjolt_marketing` 스키마를 추가했다. 게임 계정·랭킹 테이블에 연결하거나 원본 계정/점수 데이터를 변경하지 않는다. 세 테이블 RLS, 일반 anon/authenticated 역할의 직접 RPC·스키마 접근 차단, 서버 권한의 집계 조회를 확인했다.

독립 `loopjolt-acquisition` Edge v1은 JWT 게이트를 켠 상태다. 프런트의 같은 출처 서버 경유로 공개용 anon 프로젝트 키를 사용하며, 서비스 역할 키는 Edge 내부에서만 SQL에 쓴다. 공개 anon 키는 봇·사람 판별 수단이 아니다. API는 크기/필드/출처를 제한하지만 위조되지 않는 분석임을 보장하지 않는다.

원본 IP·비밀번호·이메일·핸들·전체 referrer/query를 이 측정 DB에 저장하지 않는다. capture/QA/internal 표시, 자동화 브라우저, Global Privacy Control, Do Not Track, 방문자 선택 해제를 반영한다. 표시되지 않은 소유자 방문이나 모든 봇을 자동 식별했다고 주장하지 않는다. 소유자 QA는 `/?internal=1`로 진입해 같은 탭의 집계에서 제외할 수 있고 `/?internal=0`으로 해제한다.

30일 보관·시간별 정리 작업을 실제 등록했다. `loopjolt-marketing-retention`은 `17 * * * *`, active=true, 명령 `select loopjolt_marketing.cleanup();`로 2026-09-21T04:46:50Z 다시 확인했다. 신규 환경에 pg_cron이 없다면 이제 스키마를 만들기 전에 배포가 실패하며, 작업 등록 후에도 활성 상태를 확인한다. CI용 예외 플래그는 운영 SQL에 없다. 기존 운영 DB에는 원래 작업이 정상 등록돼 있었으므로 기존 마이그레이션을 재실행하지 않았다.

저장 한도는 일 20,000건/분 1,200건/세션 600건이다. 오류가 나도 게임을 멈추지 않으며, 한도·차단·수집 장애로 누락될 수 있음을 집계에 표시한다. 새 유료 상품·광고 예산·구독은 추가하지 않았다. 기존 인프라 이용량이 무조건 0원이라는 뜻은 아니다.

## 4-2: 검색과 실제 게임 진입

홈과 주력 게임 4개에 설명적인 title/description/canonical/공유 메타데이터를 적용했다. 홈페이지의 주 이름은 Deep Descent, Gyro Drop은 별칭/내부 게임 키로 보존했다. 동시에 main에 들어온 WebSite 구조화 데이터와 검색 설명도 통합했다. 가짜 평가·검색량·국가 기록은 추가하지 않았다.

- `/descent`: 기존 Deep Descent.
- `/games/core-pins`: 검색 가능한 HTML 설명과 기존 실제 게임을 같은 페이지에서 제공.
- `/games/nova-merge`: 검색 가능한 규칙/설명과 기존 실제 게임을 같은 페이지에서 제공.
- `/games/orbit-sprint`: 기존 실제 게임과 검색 메타데이터.

기존 `/challengers/play?game=...` URL은 그대로 동작하며 새 대표주소를 안내한다. 새 페이지는 중간 소개 페이지를 추가해 클릭을 늘리는 것이 아니라 바로 플레이 가능한 기존 게임 셸이다. 사이트맵은 홈·주력 4개·초기 3개, 총 8개의 추적값 없는 대표주소다. 검색엔진 색인·순위 상승을 이미 확인한 것은 아니다.

생성 파일은 `npm run build`에서 만들어진다. 순서는 기존 search metadata → shared measurement → discovery 확장이다. 원본 저장소 템플릿과 배포 HTML이 다를 수 있으므로 최종 빌드 결과로 운영 일치를 검사했다. 반복 빌드의 중복 수정도 방지했다.

## 4-3·4-7: 실험을 강제로 성공 판정하지 않는 설정

`marketing/stage4/experiment-plan.json`에 Deep Descent 첫 문구 3개와 고정 조건을 기록했다. 다음 변수는 CTA 위치, 이후 길이다. 여러 변수를 한 번에 바꾸지 않는다. 아직 실험 영상의 신규 공개는 하지 않았다.

`decide.cjs`는 KEEP/MODIFY/KILL 외에도 DATA_GAP, WAIT, INSUFFICIENT_DATA, INVALID_EXPERIMENT, INCONCLUSIVE를 반환한다. 공통 바이오 링크로 들어온 채널 데이터만으로 특정 영상이 이겼다고 판정할 수 없다. 같은 채널·같은 관측 시간·한 변수·유효한 분모와 수집 상태가 필요하다.

초기 운영 기준: 최소 72시간, 변형별 독립 게시 3개/조회 500/태그 세션 100/시작 세션 30, 시작률 차이와 재플레이 가드. 이는 검정력 계산이나 통계적 보장값이 아니라 보수적인 초기 운영 기준이다. 자연 노출 비교는 무작위 실험이 아니며 `causalClaim=false`를 유지한다. 실제 관측값을 넣지 않은 판정 테스트의 KEEP은 서비스의 성공 근거가 아니다.

## 아직 완료라고 하지 않는 것

2026-09-21T04:46:50Z 새 집계는 `NO_DATA`, event_count=0이었다. **수집 이전 기록을 역산하지 않았고, 이것을 고객 0명이라는 뜻으로 해석하지 않는다.** 운영 경유 POST→DB 저장의 실제 최초 이벤트/별도 canary 검증은 남아 있다. mock/분리 DB 시험과 운영 읽기 검증을 실제 첫 수집과 혼동하지 않는다. 이 검증 전에는 전환율을 확정해 보고하지 않는다.

SNS 플랫폼 수치의 자동 적재·영상별 전환 증명·프로필 표시명/소개 변경·새 실험 게시·대량 콘텐츠 복제·실제 국가 대결·승자 선정은 아직 아니다. 3구간의 나머지 11개 게시물 공개도 이번 코드 배포로 완료되지 않는다. 기존 초안 15개는 그대로다.

GSC Wizard 재조회는 `400: We couldn't connect your account. Please try again.`으로 실패했다. 이번에는 연결된 속성 목록조차 조회하지 못했으므로 LoopJolt 속성 유무나 검색 클릭 0을 단정하지 않는다. 계정 재연결이 검색 데이터 점검에 필요한 실제 사용자 개입이다. 나머지 개발·현재 계측 기능은 그 재연결과 독립적이다.
