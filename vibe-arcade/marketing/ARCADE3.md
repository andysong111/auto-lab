# Arcade 3: product-accurate short-form recipe

## What is ready
Every new game supports `capture=1`: simplified framing, same game rules and graphics, forced practice, no analytics or ranked submissions. Use 720x1000 browser capture and pad to 720x1280 with deterministic hook/CTA bands. Capture mode never fakes scores, health or late-game states.

## Hero moments to record from genuine runs
- Neon Siege: battery pickup → 8-energy pulse → Aegis shield opens → actual boss destruction.
- Skyforge: near miss → narrow remaining block → 3-perfect repair → real higher floor.
- Reactor Shift: obey HOLD → DOUBLE → WAIT with a narrow release, ending in the actual cycle streak/result.

## Higgsfield usage
Only after gameplay is validated: generate a 1–2 second abstract opening or transition, using exported real character/game screenshots as references. Avoid new powers/UI or model-rendered words. The remaining footage is genuine game capture. Do not generate a different-looking playable game.

Exact `LOOPJOLT`, `@playloopjolt`, title, score and CTA are postprocessed text. No invented percentages, player counts, world records or “only 1%” claims. Budget approval and credit-cost estimate before additional generation. Prefer reusing one intro over multiple paid generations.

## QA before scheduling
Watch the final render, not only job success. Confirm brand spelling, no cut-off HUD, expected pacing, readable touch-sized content, footage/product match and a working profile link. AI-content disclosures must match the actual final asset. A code-based recording has no generative-video credit cost, but existing tool/hosting costs still apply.

Current previously scheduled clips remain the legacy games. New-edition clips must be reviewed before replacing or extending those schedules.
